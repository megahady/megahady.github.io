Git Version Control Tutorial for project_1

Overview

This tutorial shows how to apply Git version control to the following folder:

project_1/
├── aaaa.doc
├── bbbb.doc
└── cccc.doc

The instructions work from either macOS Terminal or Windows PowerShell.

What is Version Control?

Version control allows you to:

  • Track changes to files over time
  • Restore previous versions
  • See who changed what
  • Collaborate with other people
  • Store backups on GitHub

Git is the most widely used version control system.

Step 1: Verify Git Installation

macOS Terminal Windows PowerShell
git --version git --version

Expected output:

git version 2.x.x

If Git is not installed, download it from: https://git-scm.com

Step 2: Navigate to the Project Folder

macOS Terminal Windows PowerShell
cd /path/to/project_1
Example: cd ~/Documents/project_1		 cd C:\Users\YourName\Documents\project_1

Verify the files:

macOS Terminal Windows PowerShell
ls dir
aaaa.doc
bbbb.doc
cccc.doc

Step 3: Initialize Git

macOS Terminal Windows PowerShell
git init git init
Initialized empty Git repository

Git creates a hidden .git folder that stores version history.

Step 4: Check Repository Status

macOS Terminal Windows PowerShell
git status git status
Untracked files:
aaaa.doc
bbbb.doc
cccc.doc

Git sees the files but is not yet tracking them.

Step 5: Stage Files

macOS Terminal Windows PowerShell
git add . git add .

Alternative (stage individually):

git add aaaa.doc
git add bbbb.doc
git add cccc.doc

Verify:

git status
Changes to be committed:
new file: aaaa.doc
new file: bbbb.doc
new file: cccc.doc

Step 6: Create the First Commit

macOS Terminal Windows PowerShell
git commit -m "Initial project files" git commit -m "Initial project files"
3 files changed
create mode 100644 aaaa.doc
create mode 100644 bbbb.doc
create mode 100644 cccc.doc

Your first snapshot is now saved.

Step 7: View History

macOS Terminal Windows PowerShell
git log git log
commit a1b2c3d4...
Author: Your Name
Date: ...

Initial project files

Compact version:

git log --oneline
a1b2c3d Initial project files

Step 8: Modify a File

Suppose you edit aaaa.doc. Check status:

macOS Terminal Windows PowerShell
git status git status
modified: aaaa.doc

See what changed:

macOS Terminal Windows PowerShell
git diff git diff

Step 9: Save the New Version

macOS Terminal Windows PowerShell
git add aaaa.doc git add aaaa.doc
git commit -m "Updated aaaa document" git commit -m "Updated aaaa document"

Now Git stores a second version.

Step 10: View File History

macOS Terminal Windows PowerShell
git log --oneline git log --oneline
7f8e9d0 Updated aaaa document
a1b2c3d Initial project files

Step 11: Compare Versions

Compare two commits:

macOS Terminal Windows PowerShell
git diff a1b2c3d 7f8e9d0 git diff a1b2c3d 7f8e9d0

Git displays the exact changes between versions.

Step 12: Restore a Previous File Version

Restore a file from the previous commit:

macOS Terminal Windows PowerShell
git checkout HEAD~1 -- aaaa.doc git checkout HEAD~1 -- aaaa.doc

Check the file contents. Commit the restoration if desired:

git add aaaa.doc
git commit -m "Restored previous version of aaaa.doc"

Step 13: Connect to GitHub

Create a new repository on GitHub (example: project_1).

Add the remote:

macOS Terminal Windows PowerShell
git remote add origin https://github.com/USERNAME/project_1.git git remote add origin https://github.com/USERNAME/project_1.git

Verify:

git remote -v

Step 14: Push to GitHub

macOS Terminal Windows PowerShell
git branch -M main git branch -M main
git push -u origin main git push -u origin main

GitHub now stores your repository and commit history.

Typical Daily Workflow

After making changes:

git status
git add .
git commit -m "Describe changes"
git push

Useful Commands Reference

Command Purpose
git status Check status
git add . Stage all files
git commit -m "message" Commit changes
git log --oneline View history
git diff View changes
git push Push to GitHub
git pull Pull latest changes
